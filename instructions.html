Instructions and Workflow

These instructions follow the app's five stages in order. Each stage, and each page within Compile, has its own section: first what to do, then the details and terms behind it.

Feedback

Feedback is welcome. Keep a backup of anything important. Reach the developer, Kevin of SingLoud.org, at sacredharpbiblio@gmail.com.

The Five Stages at a Glance

  1. 1 Setup: open an existing singing or start a new one.
  2. 2 Capture: record the songs and markers live, during the singing.
  3. 3 Compile: after the singing, review, correct and fill in everything the live log doesn't hold. Seven pages: Event Details, Attendees, Roles, Recognitions, Memorials, Business, Song List.
  4. 4 Report: the attendance statement, in large type, to read aloud.
  5. 5 Export: preview and download the finished minutes.

The same singing carries across all five stages automatically; nothing is downloaded and re-imported by hand between them. Move between stages with the numbered steps in the left sidebar, or with the Back and Next buttons. Each stage below starts with What to do, then explains the Details and terms.

1 · Setup

What to do

  1. Open Secretary ahead of the event, ideally before you arrive. It is a single file with no install step and works fully offline once open. Use a laptop, desktop or a tablet with a physical keyboard; it isn't designed for phone-sized screens.
  2. Click Open Singing to find an earlier singing, or start a new one. If your singing is part of a recurring series, open last year's and choose New Singing in This Series; it carries the venue and Series Code forward and starts fresh on the date, officers and song list.
  3. Fill in Event, Date and Location, and the officers (Chair, Vice-Chair, Secretary, Treasurer, Arranger(s), Chaplain(s)) if known. None of this is required to start logging, but filling it in early saves guessing later.
  4. Optionally load last time's file to bring last year's attendees forward as name suggestions (see Details).
  5. Press Next to go to Capture.
Sacred Harp business-session officer elections are usually a ceremonial reconfirmation of whoever is already serving, not a new appointment. If that's the case, fill in Officers & Roles with the actual presiding officers at the very start, rather than waiting for the business session to make it "official."

Details and terms

  • Setup is the one place a singing is opened or started. No other stage has its own open or start controls. If someone emails you a Singing Record (a CSV), open it here with Open Singing, then Choose a Singing File.
  • Series Code. Links the occurrences of one recurring singing. Click Generate to get one; the generated code is deliberately not a readable word, to avoid collisions as many singings are compiled over the years. The field stays editable for matching a code someone else already uses. Previous Event ID chains each occurrence to the last.
  • Browsing a folder (series grouping) needs a Chromium-based browser: Chrome, Edge or Opera. Firefox and Safari can't browse a folder, but Choose a Singing File works in every browser.
  • New Singing Based on This One offers the same continuation from inside any open singing, useful when you opened a single file rather than browsing a series.
  • Once a singing is open, its name, date and status stay visible at the top of the screen in every stage.
  • Schema version. A file with a schema version this build doesn't recognize, but isn't newer, is flagged so you can double-check the result, and opening still proceeds. A genuinely newer schema is blocked outright, because re-saving could silently drop what it added.
  • Load last time's file brings forward only the people who attended that singing (led, held an office, or were marked visitor, VIP, out of town, present or added by hand). They suggest in name boxes and appear gray on Attendees until logged.

2 · Capture

What to do

  1. For each song, type the Leader, then the Page (for example 123, 45t, 45b for a top or bottom page), and press Enter. No button needed. More than one person can lead a song: type the first name, then type “and” or a comma, then the next name. Name suggestions start again after each.
  2. Use the Notes field to write down anything different about the lead: a child or other family member leading with them who isn't otherwise registered, an anecdote, a dedication to someone. You can edit or remove it later, but getting something in while it's happening makes it easy to remember.
  3. Use Recess, Lunch, Announcements, Prayer and Business Meeting to mark what happens between songs. For an announcement, type who made it in the Leader box first. At each Recess a reminder asks you to use the break to enter attendees who haven't led (see Attendees).
  4. Tag a song when it applies: Call Back (the leader who brings the class back together after a break) or Special. For a memorial lesson or singing school, use the Memorial Lesson or Singing School mode buttons.
  5. To fix a recent entry, tap it in the log and edit it in place. The same page, leader and duplicate checks apply.
  6. For a new day or a change of venue, press Start New Session (see Details).
  7. Download or copy the CSV during the event and again at the end, as a backup.

Details and terms

  • Titles look themselves up from the selected songbook. If a page could mean two songs, you are asked for top or bottom. If a page doesn't exist in the book's index, you are asked to confirm before it is added, so a typo isn't logged as real.
  • Top and bottom pages. Use t or b only when a page holds two songs that both start on it. If a page carries the continuation of a song from the previous page plus one new song starting lower down, that new song is the only one that starts on the page, so it gets no b; there is nothing to tell apart.
  • Tags and who they credit. Whoever leads a Memorial-tagged song is credited as the Memorial Lesson Leader; there is no separate place to type that name, so fix the Leader on the tagged song itself. On the Song List a song can also be tagged Opening (the song that calls the class to order, even if a prayer or other entry was logged first) or Closing (the last song).
  • Modes. Memorial Lesson and Singing School stay on, with a banner, until you press End; songs logged meanwhile belong to that lesson or school. While Memorial Lesson is on, For Sick/Shut-ins and For Deceased mark whom a song is for.
  • Sessions. A singing can span more than one session: a second day, a change of venue, or any distinct segment of the same event. Start New Session stays inside the same event and the same file. It reopens the date and location fields, lets you add a label (for example "Day 2") and change officers only where they differ, then you confirm. Nothing already logged changes. A session can carry its own date, location, label and officers.
  • Saving. Capture saves to this browser automatically; a status line shows "Saved locally at [time]" or a warning if local saving isn't working. Reopening on the same device and browser restores where you left off. Local saving is not a backup, so download or copy the CSV too. An optional automatic backup download (off by default) saves a copy to your Downloads folder every few minutes.
  • Marker text. Typing in Notes before pressing an announcement or business marker saves it as that entry's note; it prints in the minutes at that point.

3 · Compile

What to do

  1. Open the stage. What was logged is already there: Event Details, Roles and the Song List fill in from the record, with no file to choose.
  2. Work down the sub-pages in the sidebar: Event Details, Attendees, Roles, Recognitions, Memorials, Business, Song List. Each has its own section below.
  3. Clear anything flagged before exporting: a row missing a name or page, an unrecognized tunebook code, or a likely duplicate spelling of a leader. A proofing pass now is easier than a correction after publication.
  4. Press Next to reach the Report.

3a · Event Details

What to do

  1. Check the name, date, location and book(s) used.
  2. Enter the annual or edition number (for example "2nd annual") separately from the name.
  3. Leave Total attendees (raw number) blank unless you can't enter everyone's name (see Details).

Details and terms

  • Name of singing is the proper, stable name (for example "Dahlonega Shenandoah Harmony Singing"). The SHMHA export keeps this printed title fixed; every other export bakes in the number ("2nd Annual Dahlonega Shenandoah Harmony Singing").
  • Series Code, Event ID, Previous Event ID let related singings (this year, last year, next year) be recognized as one series across separate files, without any shared database. Leave blank for a one-off event.
  • Total attendees (raw number) is only for when you can't enter names for all attendees and need a head count or registration total instead. A number typed here replaces the counted total on the Report's All-sessions statement and in Minutes Maker. Leave it blank whenever you can: the Secretary should enter every attendee's name on the Attendees page, whether or not they led a song.

3b · Attendees

What to do

  1. Enter every person who came, whether or not they led a song: search for a name, and if nobody matches, press Add attendee. Do this during a Recess if you can.
  2. Check spellings. To fix one, edit the name; to merge two entries, type the exact name of the other. The fix applies to every song, officer field and list in the singing.
  3. Mark visitors, out-of-town singers, VIPs, donors and anyone thanked.
  4. Optionally add a phone number or email.

Details and terms

  • The page lists everyone named anywhere (leaders, officers, and anyone you add) once each. Filter by All attendees, people with or without contact info, or people who have not led a song (one filter at a time).
  • Each attendee can have a location and these marks: visitor / first-time singer, from out of town (with the location), visitor / VIP who was not a singer, donor / contributor who was not a singer, and thanked. The marks fill the Recognitions lists, which are display-only; edit them here.
  • Counted as attendees: people named in this singing (a leader, an officer, a name in another entry), marked visitor, VIP or out of town, added by hand, or ticked Present. Not counted: people known only as a donor or as thanked, saved contacts with no entry in this singing, and carried-over names.
  • Gray rows are names carried over from last time's file, donors, thanked-only people, and contact-only records. Tick Present for anyone who actually came; ticking it counts them and turns the row normal. Anyone you log counts automatically and their Present box is locked on.
  • Contact details are private. Phone numbers, emails and notes are stored inside the singing's master CSV. Export offers a version without them, Attendees can download a mailing list, and Capture warns whenever the record carries contacts. Share the "without contact details" file, not the master.

3c · Roles

What to do

  1. Fill in who served the class: Chair, Vice-chair, Secretary, Treasurer, Arranger(s), Chaplain(s) and the other roles. Leave blank whatever wasn't observed.
  2. Add more than one person to a role by typing a comma or the word "and"; name suggestions restart after each.

Details and terms

  • Suggestions are drawn from the Attendees page.
  • Only the Chair, Vice-chair and Secretary reappear in the one-line roster at the end of the minutes; everything else is woven into the write-up. Export's Roles to include in the closing roster changes that.
  • Officers who differ in a particular session are set on the Song List page's Sessions section.
  • The role someone holds is also how an announcement is credited: "The Treasurer, Jim Glaser, made an announcement."

3d · Recognitions

What to do

  1. Review the lists of visitors, first-time singers and VIPs; out-of-town singers; people thanked; and donors. These are filled in from the marks on Attendees.
  2. Type the Sick and shut-in and Deceased since last singing lists freely.

Details and terms

  • The lists from Attendees are display-only here; to change one, change the mark on Attendees.
  • Sick and deceased people are not attendees, so those two lists stay freeform.
  • These are ambient recognitions, not tied to one moment in the service. For the memorial lesson itself, use Memorials.

3e · Memorials

What to do

  1. Add one row per name for the sick and shut-in and the deceased lists.
  2. Add dedications and remarks as free text.

Details and terms

  • The Memorial lesson leader is derived from whichever songs are tagged Memorial and is not editable here. To change it, fix the Leader on the tagged song.
  • A Note on a Memorial-tagged song isn't printed; the names belong on this page.

3f · Business & Announcements

What to do

  1. When this page appears in the sidebar, write out longer text in the box for each Business Meeting or announcement.
  2. Fill in the next singing's date, location and chair, thanks to hosts, and closing remarks.

Details and terms

  • The page appears only once a Business Meeting is entered or an officer (Chair, Treasurer and so on) makes an announcement.
  • Each box is the Notes of that entry on the Song List: what you type here prints in the minutes at that point and shows on the Song List. There is no separate copy.
  • If one officer makes more than one announcement in a session, they are numbered ("Treasurer announcement 1 of 2") on the Song List and in the minutes ("made the first announcement"). A single announcement is not numbered.
  • A Business Meeting entry can carry a report tag (Treasurer's, Secretary's or Chaplain's Report, or Chair's Remarks) on the Song List.

3g · Song List

What to do

  1. Scan the rows. Rows in red are missing a title or page; fix them.
  2. Fix mistaken pages and normalize leader names. Similar spellings are clustered so you can merge them to one canonical form.
  3. Drag rows to reorder if needed.
  4. Add dedications such as "in memory of Buell Cobb" in Notes / Dedication; they print right after the page number.
  5. Assign a Work Code to any tunebook that doesn't have one, in Book Handling.
  6. If the singing has several sessions, check each session card (see Details).

Details and terms

  • Sessions. When a file has more than one session, a Sessions section appears: one card per session with its own location and any officer differences. Each officer has three choices: use the event default, set none for that role this session, or name a different person for just that session. Two sessions sharing a date, location or label are still tracked separately.
  • Tags: blank, Call Back, Memorial (Sick), Memorial (Deceased), Opening, Closing, Special, Singing School. For Business Meeting entries the tag is the report type.
  • Book Handling. Non-default tunebooks need a short code assigned once, here. See Reference for the two code systems.
  • Entries can be added by hand; a Capture file is the normal path, not a requirement.

4 · Report

What to do

  1. Open the stage and read the statement aloud at the singing's close or business session. Nothing here is typed in.
  2. If a number looks wrong, go back to Attendees (to add or fix names) or Event Details (to enter a raw head count).

Details and terms

  • The statement reads, for example: "The 9th Annual Maryland All-Day Singing consisted of 62 total attendees, with 38 singers leading a total of 112 songs."
  • A singing with more than one session shows a statement for each session, then one for all sessions (a four-day convention shows five). Each session's count is the people named in that session's entries or holding an office that session. The All-sessions statement counts the whole singing.
  • A raw number typed in Event Details replaces the counted total on the All-sessions statement only.
  • A short note under the statement says which basis the number uses.

5 · Export

What to do

  1. Choose the Type of output first: Minutes Maker, Simple List, or SHMHA Minutes Book.
  2. Set the wording options that apply to it and read the live preview. It updates immediately with every change you make anywhere.
  3. Choose a format and export. Download the Master CSV as well; it is the complete, authoritative record.

  • Minutes Maker options. Show the song number, the title, or both on each call-out (if you uncheck both, the one it has is used); show a song's source on every call-out rather than only when it differs from the day's default book; Show time called (shared with the Simple List); ALL CAPS; Number of attendees present, leaders and songs in the summary line; Roles to include in the closing roster (All roles, or any individual role); Cite the page in parentheses (“North Carolina” (3b) instead of on page 3b). Per-song book identifiers can be a SingLoud work code, an SHMHA code, or the book's title.
  • Wording & presentation (narrative minutes): recurring date pattern for annual singings; five opening-paragraph styles (A to E); presiding title; opening and closing prayer credit phrasing. To credit a specific title such as "Elder", type it into the Chaplain name on Roles.
  • No names. A checkbox for singings whose minutes don't name individual leaders; song attribution is dropped throughout and the wording adjusts.
  • SHMHA Minutes Book always follows its own fixed format regardless of those options: printed-book songs are identified by page number only, and a title only when there is no page to give (an "Other" source).
  • The Master CSV. There is one master file per singing, not one per stage. The other formats are one-way publication outputs generated from it; they are not meant to be re-opened and don't replace it.
  • Planned, not yet available: Planned additional output profiles (for example Website, Archival Record, Data Exchange), and chapter lists or timestamp markers for a long recording, generated from the order and timing already captured.

Reference

SHMHA Guide

The SHMHA Guide in the sidebar's Reference section holds the Sacred Harp Musical Heritage Association's own instructions for submitting minutes and its abbreviation table. Use it to double-check an SHMHA export and for anything a rules-based export can't judge for you (brevity, verifying spellings).

Two code systems for tunebooks

  • SingLoud.org Work Codes are used internally and in every export except the SHMHA submission.
  • SHMHA abbreviations are used only in the SHMHA Minutes Book export, translated automatically from the Work Code you assign.

Neither is more "correct"; they are the two published vocabularies the suite outputs today. The Type of output on Export determines which applies.

How tunebooks are recorded

Not every tunebook is known in the same depth. Books sit at one of four cumulative levels; the level is roughly how many things we know.

  • Level 0 — Other. Just a name typed in passing. It appears in the CSV as the book value Other, and its songs are identified by title.
  • Level 1 — Basic record. The title plus whatever scant details are on hand. The name is recognized, but song titles can't be looked up by page.
  • Level 2 — Indexed. A complete page-by-page song index. This lets Capture suggest a title as soon as you type a page number, and lets Compile catch a page that doesn't exist in the book. Most books the suite ships with are here.
  • Level 3 — Enriched. A dedicated file per edition holding, or building toward, the full scholarly record: attribution, concordances, editorial and publication history, bibliography. Level only means the file exists, not that it is finished.

All of this lives in one file, tunebook-library.js, published by the Tunebook Registry. Secretary reads tunebook data but never changes it. Only Bibliographer, a separate application, edits it; nothing in Secretary depends on having it open.

Troubleshooting

Capture won't resume my CSV

Capture is strict when resuming a file: the column headers and schema version have to match exactly, since it's designed to resume an in-progress session precisely. A file edited in a spreadsheet program can sometimes reorder or rename columns; download it again from Capture if possible.

A file won't import into Compile, or imports with almost nothing recognized

Compile is much more tolerant than Capture — it matches columns by name, recognizes several alternate column names, and will still import a file with only some recognizable columns, flagging what it found. If a file truly imports with nothing usable, check that it has at least a Leader/Caller, Page, or Notes column under some name Compile recognizes.

"Old schema" or version-mismatch message

This behaves differently in each app, and Compile itself behaves differently depending on the specific mismatch. Capture blocks importing a file from a different schema version outright, since it's designed to resume a session exactly. Compile is more tolerant of an unfamiliar-but-older or otherwise-unrecognized version: it flags the mismatch and asks you to double-check the result more carefully than usual, but the import still proceeds. A file reporting a schema version genuinely newer than what the current build of Compile understands is the one case Compile also blocks outright, rather than just flagging — re-exporting an unfamiliar newer schema through this build's own current-schema header could silently discard whatever that newer schema added, which is a real data-loss risk, not just an unfamiliar label. Open a file like that in a version of Compile that actually supports its schema version instead.

Missing or unknown tunebook code

Assign the book a Work Code on the Song List tab's Book Handling section. If the SHMHA export shows a code you don't recognize, check the SHMHA Guide (in the Reference section of the left rail) for its abbreviation table.

Browser storage unavailable

The Capture stage will show a clear warning rather than silently failing to save. Download or copy your minutes right away if you see this, since local autosave isn't working on this device/browser combination.

Preview doesn't match what I expected

Check which Type of output is selected on the Export stage (Minutes Maker, Simple List, or SHMHA Minutes Book) — they apply different style rules. Also check the Song List tab for a row that's still flagged (missing page, unresolved tag, or similar), since an unresolved row can print differently than a finished one.

Opening a singing in Setup doesn't seem to reach Secretary or Compile

It should — visiting either stage for the first time after opening or creating a singing hands that singing to the stage automatically, using the same real import logic a manual file load would. If a stage still looks empty after visiting it, that's worth reporting rather than assuming it's expected; it's not.

I opened Compile without a Capture CSV

That's fine — you can add songs by hand on the Song List tab. Importing a Capture file is the normal path, not a requirement.
